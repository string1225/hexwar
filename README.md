# 六边形战争 · HEXWAR

从一格领地开始，扩张、调兵、建立补给线。一个面向微信小游戏的单人回合制策略游戏，同时提供浏览器试玩版。

## 快速开始

需要 Node.js 22.13 或更高版本（后端使用内置 SQLite）。

```sh
npm install
npm run dev
```

打开 <http://127.0.0.1:5173>。选择地图规模和敌军数量后开始战役。开发服务器只监听本机，不会公开到局域网。

```sh
npm test       # 规则、存档、UI、微信适配测试
npm run build # 生成两个发布目录
npm run check # 测试 + 构建
```

构建输出：

- `dist/web/`：可部署到静态服务器的浏览器版本，无后端依赖。
- `dist/wechat/`：微信小游戏代码及资源。

## 导入微信开发者工具

1. 运行 `npm install` 和 `npm run build`。
2. 在微信开发者工具中新建 / 导入**小游戏**项目，选择本仓库根目录；根目录 `project.config.json` 已配置 `compileType: game` 和 `miniprogramRoot: dist/wechat/`。
3. 项目已绑定小游戏 AppID `wxacd4dbd0f3d625e8`。使用有权限的微信账号登录开发者工具进行模拟和真机预览。
4. 每次修改源码后重新运行 `npm run build`，再编译。

每步自动保存本机进度。右上角保存图标打开独立存档弹窗，微信版可手动备份当前战役或读取云端战役；读取会替换本机进度。打开云存档不会自动覆盖任何进度，断网仍可正常玩。浏览器版保持独立本地存档。未接入广告、付费、数据分析或多人对战。

微信客户端使用 `wx.createCanvas`、`wx.createImage`、触摸事件及本地存储；包含像素比、顶部胶囊区域和底部安全区适配。平台配置参考 [微信官方小游戏示例](https://github.com/wechat-miniprogram/minigame-demo)。实际真机表现仍须在微信开发者工具及 iOS / Android 微信内验收。

## 微信 CI 预览和上传

复制 `wechat-ci.example.json` 为被 Git 忽略的 `wechat-ci.local.json`，填入上传密钥的本机绝对路径，也可使用 `WECHAT_PRIVATE_KEY_PATH` 环境变量。

```sh
npm run wechat:check    # 校验 AppID、RSA 上传密钥和机器人编号
npm run wechat:preview  # 构建，生成 artifacts/wechat-preview.jpg 扫码预览
npm run wechat:upload   # 构建，上传微信开发版本；不自动提审或正式发布
```

上述流程通过 `miniprogram-ci` 调用微信平台，不依赖开发工具 CLI 服务端口。预览和上传经 SSH 使用 139 的网络出口，上传密钥留在本机；若开启此 AppID 的「小程序代码上传」IP 白名单，需加入 `139.224.12.141`。这与服务器域名白名单是两项独立设置。App Secret 仅用于服务器。

## 怎么玩

1. 选择小型（37 格）、中型（91 格）或大型（169 格）地图，设置 1–5 个电脑敌军。
2. 你是绿色的翡翠军团。每个势力以 1 块领地、18 兵开始，中立格随机有 1–6 兵。
3. 点击己方格子，再点击相邻目标。用 `−` / `+` 或 `1/4` / `1/2` / `全部` 调整出兵量，点击「设定指令」。此时只保存计划，不改变兵力或领地。
4. 同一回合可规划多条指令，从不同领地出兵，也可从同一格分兵。点击「结束回合」后才执行自己的攻击和运输，再由电脑依次规划并结算；整轮结束后所有已占领地块各增加 1 兵。
5. 选择「本回合」可在结束回合时执行一次；相邻友军选择「每回合」可持续调兵。同一起点可设置多个方向；重复设定同一起点和目标会更新兵力和执行频率。点击「本回合指令」可查看、编辑或取消。设置后仍保留当前指令，底部面板和地图位置固定。
6. 消灭所有敌方彩色格子即获胜；不需要占领所有中立格。丢失最后一块己方领地则失败。

拖动地图平移；使用 `+` / `−` 缩放，`◎` 复位。桌面可使用滚轮缩放、空格结束回合、Escape 关闭弹窗。再次点击已选为目标的友军格可将它切换为新的出发点。

战斗内部继续使用 `1 / (1 + (守军 / 出兵)^k)`，`k = ln(19) / ln(3) ≈ 2.68014`。胜利时剩余 `max(1, 出兵 − ceil(守军 / 2))`；失败时出兵全部损失，守军剩余 `max(1, 守军 − floor(出兵 / 2))`。游戏界面和玩法说明不显示胜率、百分比或公式。攻占成功直接更新地图，不弹提示。

每轮结算顺序为：**玩家结束回合并结算计划 → 各电脑依次规划并结算 → 所有占领地 +1 → 新一轮**。本回合和每回合指令共享出兵前的兵力快照，按设置顺序分配兵力，至少留 1 兵，不足按余量执行；本次新收到的兵不能再次派出。一次性指令执行后清除，持续指令保留至取消或端点失守。单格兵力上限 9999。电脑每回合从每个原有领地最多规划一条指令。未执行计划随存档保存，旧存档自动迁移。

## 项目结构

```text
src/core/         平台无关的确定性规则引擎、六边形坐标
src/ui/           共享 Canvas 界面、输入处理、战役控制
src/platform/     浏览器与微信生命周期 / 图片 / 存储 / 输入适配
server/           微信登录与云存档 HTTP API（Node 内置 SQLite）
deploy/           Nginx 路由、systemd 服务与部署脚本
assets/           原创 Logo
scripts/          本地开发服务器、双端构建
tests/            规则、回归、模拟对局及平台契约测试
docs/             方案评估、视觉设计说明
```

首版范围、设计取舍和未来联机方案见 [方案评估](docs/DESIGN.md)。Logo 及其生成说明见 [视觉设计](docs/BRAND.md)。

## 验证边界

自动化测试覆盖地图连通性与出生分布、战斗概率与伤亡、回合轮转、自动运输、胜负、存档校验和长局状态不变量；共享界面与微信适配还通过模拟平台测试。浏览器需进行真实点击、手机 / 桌面布局、刷新续战的人工验收。

微信 API 模拟测试及 CI 预览生成不能替代微信开发者工具或真机测试。多人实时联机属于后续阶段，当前不提供房间或匹配入口。
